## 一、竞品现实与我们的位置

调研到的三组对手（子代理配额受限，只做了定向核实，但关键事实确凿）：

| 对手 | 是什么 | 强在哪 | 它的天花板 |
|---|---|---|---|
| **Muse**（muse.ai） | Meta 2026-09 发布的个人 AI Agent，模型 Muse Spark，给每人一台云端电脑 | 分发 + 免费 + 通用代办能力，12 天下载反超 ChatGPT | 不在"本地"、不在"人格"、不在"关系"。通用助理没有性格，用户不会产生感情 |
| **OpenClaw**（原 Clawdbot → Moltbot，Peter Steinberger） | 开源自托管个人助理，接 WhatsApp/Telegram/Discord，在自己电脑上干活 | 渠道接入 + 本地执行 + 开源爆火 | 助理是"一个"，不是一群；助理之间没有社交；UI 是 IM，不是"相处" |
| **Kindroid / Nomi / Character.AI** | AI 陪伴，主打可定制人格、语音、自拍、Learned Context 自主记忆 | 人格深度、亲密度、情感反馈 | 闭源订阅、内容审查、单人关系、无法自己部署模型 |

**结论**：通用能力（办事）已经免费且巨头化，通用 Agent 不值得追。我们唯一还能占的位是——

> **本地、开源、免费、可离线的「助理群像空间」：一群有人格、会成长、能协作的助理，和你一起生活与工作。**

差异化五点：
1. **群像而非单体**：助理之间有社交关系（互相引用经验、群聊里补位、传话接力可视化）——开源世界几乎空白。
2. **人格是一等公民**：不是 system prompt 文本框，而是可视化人格卡（名字/物种/生日/性格三维/音色/口头禅/关系值）。
3. **进化是可见的**：每条 👍 都变成助理档案里的"新技能卡"，写明"因为你说了 X，我现在会 Y"。
4. **本地主权**：key 不出本机、可切任意 OpenAI 兼容供应商、可离线小模型（与 Muse 的云端路线正面相反）。
5. **可分享的人格文件**：`.rypersona` 单文件带走一个助理（形象+人格+声音+记忆种子），社区可互换（Kindroid 做不到）。

## 二、产品愿景（一句话与三条不做）

**一句话**：RyAgent 是你电脑里的**客厅**——几个你亲手养成的 AI 助理住在这里，你和它们说话、它们互相搭话、它们因为和你相处而改变。

**不做**：① 不做通用任务代理（那是 OpenClaw/Muse 的战场）；② 不做内容审查型社交；③ v1 不做账号云同步、不做移动端、不做训练模型。

## 三、核心交互范式：三层结构（跳出聊天气泡）

现有产品的共同点是"消息列表 + 左右气泡"。RyAgent 改为**三层**：

### 第 1 层 · 空间层（Space）— 主视图是"在场"，不是"列表"

- 主界面是一间 2.5D 的空间，每个助理有一个**席位**（2D 角色立绘 + 呼吸/眨眼/看向发言者的微动画，SVG/Rive 实现）。
- **私聊 = 进入某个席位特写**：镜头推近，主角在中央，用户的输入框是"对讲机"，发出的话飞入场景。
- **群聊 = 圆桌**：多个席位围绕一张桌子，被 @ 的角色亮起并前倾，其余角色降低对比度（视觉降噪）。
- **调度接力 = 传话动画**：Ryen 把"话"传给 CodeBot 时，一个可见的令牌从 Ryen 滑到 CodeBot，CodeBot 点亮，其余静音——这是我们已有的 dispatcher 数据可视化能力，只是把它从"右栏日志"搬进舞台。
- 降级与可访问性：保留"经典对话视图"开关（列表流 + 虚拟化），空间视图是可选项，性能设备自动降级。

> 这是与"所有 chat 产品"最大的区隔：**消息是场景的一部分，不是列表的第 N 行。**

### 第 2 层 · 对话层（Conversation）— 内容本身被设计

| 元素 | 现状 | 新设计 |
|---|---|---|
| 用户消息 | 右对齐灰气泡 | 输入框在舞台底部中央，发送后文字"上浮"为字幕卡，停留 3 秒后归档到右侧时间轴（不刷屏） |
| 助理发言 | 左对齐气泡墙 | 字幕卡 + 角色嘴型/呼吸动画 + 正在输入的呼吸态（不是静止光标） |
| 工具执行 | 灰色日志行 | 舞台上的"动作卡"：读文件=卡片展开、跑命令=终端小窗、产出文件=可拖拽的文件卡片 |
| 流式停顿 | 静止光标（走查实测停滞 40s 无反馈） | 角色进入"思考中"姿态 + 已用时秒数 + 停止按钮（取消是一等公民） |
| 群聊多声部 | 消息混在一起 | 发言者名字 + 音色色环 + 座位高亮；非发言者消息降 20% 对比度 |

### 第 3 层 · 档案层（Dossier）— 助理的"生命档案"

右栏不再是工具面板，而是每个助理的档案页：

- **名片**：立绘（2D 头像 → 后续 VRM 3D）、名字、物种、生日、一句话人设、性格三维雷达、音色试听。
- **它记得**：记忆卡片墙（可编辑、可删除、可钉住、可"这条记错了"一键纠正）。
- **它学会的**：playbook 技能卡（带生效证据：3 次命中、什么时候用的）。
- **我们之间**：相遇时间、共同记忆时间线、亲密度（由互动频率与深度自然累积，不做刷数值游戏）。
- **进化时刻**：👍 后弹出"Ryen 学会了：先确认时区再排程"，点击直达技能卡——把内核已有的进化闭环变成产品的情绪高潮。

## 四、人格系统（Persona）：从 prompt 字段升级为一等公民

### 数据模型

```ts
interface Persona {
  identity: { name; species; birthday; tagline; avatar2d: string; vrm?: string }
  voice:    { provider: 'local' | 'cloud'; voiceId; speed; pitch }
  personality: { openness; precision; humor; warmth }  // 0-100，编译为 prompt
  quirks: string[]        // 口头禅、小习惯、招牌反应
  style: { speakLength; emojiRate; formality }
  relation: { bond: number; firstMetAt; sharedMemoryIds: string[] }
  state:    { mood; energy; lastActiveAt }
}
```

### 人格编译器（确定性、可预览）

- 三维/四维滑杆 → 结构化 prompt 片段（不是黑盒）：`warmth 高 → 语速慢、常主动关心、称呼亲密`。
- 编译结果在创建向导里**实时预览**并允许逐条手改覆盖（用户永远保留最终控制权）。
- 情绪状态 `state.mood` 轻微影响回复风格（最多一条风格提示，不做数值干预）——廉价感红线：不显示"好感度 +5"。

### 创建向导 = "遇见"而不是"填表"

1. **选起点**：预设原型卡（橘猫 Ryen / CodeBot / 学者 / 写作 / 生活管家 / 空白）——每个原型带完整声音与立绘，克隆即用。
2. **起名 + 形象**：DiceBear 单一风格族（收敛 6 族为 2 族）做二维头像，预留 VRM 槽位。
3. **调性格**：四维滑杆 + 口头禅输入，实时预览 prompt 与示例开场白。
4. **选声音**：预置音色试听（本地 Kokoro/Piper 优先，云 TTS 可选），说话风格与性格联动（严谨角色语速慢半拍）。
5. **见面**：由助理**主动打招呼**（Ryen 的第一句话写死得有趣），而不是等用户开口。

## 五、品牌图形（当前最弱一环，3.5/10）

- **一只猫，统一到底**：现在项目里有四只不同的猫（Fluent Emoji 黄猫图标、手绘橘猫、Lucide 线猫、废弃领结猫）。重绘为**一只极简几何橘猫**：圆头 + 三角耳 + 琥珀渐变 squircle 底，产出 16/32/48/256/512 五档 + 单色剪影版，图标、导航、吉祥物、启动画面、favicon 全部同源。
- **头像体系收敛**：DiceBear 从 6 族砍到 2 族（dylan/open-peeps 扁平人物 + funEmoji 机械），内置模板固定语义种子，不再随机混搭。
- **图标语言统一**：Fluent Emoji 从功能图标位清退（欢迎页 chips 改 Lucide），emoji 只用于用户内容。
- **图标网格**：Lucide 尺寸收敛到 12/16/20/24 四档，修复 `Icon.tsx` 的 `replace()` 只替换首个 `stroke-width` 的 bug。
- **空态插画**：unDraw 风格可改色插画，为"空会话/空记忆/空产物/首次见面"各配一张。

## 六、内核与性能（吸收评审，列为硬指标）

| 指标 | 现状 | 目标 |
|---|---|---|
| 冷启动首屏 | ~2.5s（1.27MB 内联单 chunk + 主进程串行等 server） | ≤ 1.2s（渲染层由 127.0.0.1 server 伺服，恢复缓存与 code splitting） |
| 流式首 token | 串行 recall→compile，记忆+进化全串行 | ≤ 1.5s（两者并行 + 服务端 delta 合批） |
| 流式渲染 | 每 token 全量拷贝消息数组 + 每气泡 JSON.stringify | O(1) 版本号比较 + 定点拷贝 |
| 长会话 | 无虚拟化，150 条硬截断 | 1000+ 消息流畅（@tanstack/react-virtual） |
| 上下文 | 单聊零裁剪，必炸 | token 预算裁剪 + 摘要滚动（与群聊对齐） |
| 工具调用 | 串行 | 并行（对齐 pi 默认） |
| 取消 | 不存在 | AbortSignal 贯穿 router→loop→llm 流 + 停止按钮 |
| usage | 管道断头 | 落库 + 会话级成本显示 |

**内核修复清单**：memory/evolve 改走 LlmRuntime（消灭写死 SiliconFlow 的旁路，多供应商叙事才成立）；Curator 传入条目列表（否则 playbook 只会加不会改）；衰减基准改 `lastAccessedAt`（让"越用越牢"成立）；抽取 prompt 加 few-shot + 相似度阈值兜底。

## 七、视觉与动效规范（数值级，回应"方方的/不丝滑"）

```
圆角梯度：8 / 12 / 18 / 28 / pill      （当前 8/12/16 → 大圆角或去边框）
边框策略：暗色下去掉 1px 边框，改用 2% 明度差 + elevation 阴影；亮色保留极浅边框
动效时长：hover 120ms / 进出场 180ms / 布局变化 240ms
动效曲线：--ease-out cubic-bezier(.22,.8,.36,1)；spring cubic-bezier(.34,1.4,.64,1) 用于 badge/发送确认/选中指示
必备规则：所有弹层与提示必须有退场动画（当前全部瞬间消失）；prefers-reduced-motion 全局支持
禁用规则：无限循环装饰动画（当前欢迎页猫 4s 浮动 + 星星旋转）；消息气泡 hover 位移（当前 translateY(-1px) 造成文字抖动）
暗色主色：同色相提饱和而非降明度（当前主色成"泥巴棕"）
无障碍：徽标对比度 ≥ 4.5:1（当前暗色未读徽标约 1.6:1，违规）；focus-visible 白名单补齐
```

## 八、路线图（每阶段有验收标准）

| 阶段 | 内容 | 验收 |
|---|---|---|
| **P0 止血**（2 天） | 隐藏原生菜单栏；新建 Agent 弹窗可滚动（当前保存按钮不可达）；模板轨传参（当前点"翻译"弹出通用助理）；徽标对比度；清理测试数据 | 走查 P0 项归零 |

| **P2 设计系统 + 对话层重做**（2 周） | token 升级；退场动画体系；spring 曲线；对话页改为"舞台 + 字幕卡 + 动作卡"；经典视图并存 | 设计规范落地 + 60fps |
| **P3 人格系统**（1.5 周） | Persona 模型 + 编译器；创建向导；档案页；记忆/进化可见化 | 从零 3 分钟内造出一个有人格的助理 |

| **P7 生态** | `.rypersona` 分享；模板市场；cordis 插件化做实 | 他人可一键导入你的助理 |

## 九、需要拍板的 5 个决策点

1. **主范式**：空间/群像为主 + 经典列表并存（推荐），还是直接全量空间化（风险高）？
2. **3D 投入**：P6 才做 VRM（推荐，2D 席位先用 Rive/SVG 打磨），还是提前到 P3？
3. **声音**：本地 TTS 优先（离线、体积可控）、云 TTS 可选（推荐），还是先只做云（省事但断网即哑）？
4. **取舍**：为了角色中心感，是否接受 v1 砍掉一些"生产力痕迹"（飞书式长列表、复杂筛选）？
5. **品牌**：Ryen 保留为默认橘猫，还是引入"物种系统"让所有默认助理同一世界观？
