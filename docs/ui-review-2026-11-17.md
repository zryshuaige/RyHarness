## 2. 证据缺口（P0 先修，否则复评没有像素依据）

像素轮发现入库截图本身不可信——**这是本轮最先要销账的缺陷（D13）**：

- `capture-me.png` / `capture-plugins.png` / `capture-providers.png` 画面相同（均为 我的→个人资料），暗色三张 likewise。
- `dark-capture.png` 与 `dark-capture-chat.png` 字节相同（暗色「欢迎」张拍成了恢复出来的会话）。
- `scripts/verify-shots-fresh.mjs` 只比 mtime、且只扫 `.ts` → 错页 / 重复 / 过期截图都能过门禁。
- `scripts/capture-window.ps1` 入库即损坏（每个大写 R 被写成 y：`yyAgent`/`GetWindowyect`/`System.yuntime`…），默认标题还停在旧产品名。

**根因（firsthand 定位，三条独立 bug）**：

1. `gotoTab('插件')` 在 rail 上找含「插件」的 `.rail-tab`——**不存在**（RAIL_TABS = 聊天/RyVibe/通讯录/我的；插件是「我的」子页）。旧 `gotoTab` 忽略 click 脚本的 `false` 返回，静默留在原页 → 插件张拍成个人资料。
2. 供应商张依赖 `.provider-picker`，但它在 models section 里，`styles-me.css` 把非当前 `[data-section]` 整段 `display:none` → `querySelector` 找得到、`scrollIntoView` 是空操作 → 拍到页首（个人资料）。
3. 暗色欢迎张：`activeId` 懒恢复 `ryharness-active-conversation`（310dfd2 修复后 reload 会恢复上次会话）→ 切主题 reload 后「欢迎」其实是聊天页。

**P0 修法（已实施，见 §11）**：`gotoTab` 找不到页签即抛错；新增 `gotoMeSection(label)` 点 `.me-nav-item`；
**assert-before-capture**（拍前量矩形断言目标在视口，轮询重试后仍不符即 fail loud）；welcome 张拍前清恢复键 + 两栏收起态；
场景扩到 Me 九子页 × 双主题；`saveShot` 同轮哈希互异守卫；`verify-shots-fresh` 扫 `.ts/.tsx/.css` + 同主题哈希互异；
ps1 恢复 R 字符并改默认标题为 RyHarness；capture 兜底 watchdog 90s→300s。**先重拍全套 before 基线**再复评密度。

## 4. 缺陷台账 D1–D13（代码轮修正后）

每条含：现象 → 根因（firsthand）→ 修法 → 销账阶段 → 状态。

- **D1 浅色发灰发飘**：`--bg-app:#FAF7F2` + 白卡 + 10% 描边，面不分层。
  根因：浅色 L* 步不够，`--edge` 太淡。**无任何测试钉 `--bg-app`/`--edge` 的 hex/alpha**（grep 证实）→ 纯 token 改值 + 原生壳同步，contrast 探针兜底。
  修法：`--bg-app #FAF7F2→#F5F1E8`、`--bg-subtle #F4F0E8→#EDE7DB`、`--edge .10→.16`、`--edge-strong .16→.26`、`--divider .09→.12`、hover/active `.045/.085→.055/.10`、secondary/tertiary 加深保 AA；暗色仅 `--edge .09→.12`/`--divider .07→.10` 对齐。**同步** `electron/main.ts` `backgroundColor`+`TITLEBAR_OVERLAY`（暗色现值 `#14110E` 与 `--bg-app:#101114` 漂移，一并修）+ `index.html` splash token。→ **P1**。
- **D2 尺度失控密度低**：旧图通讯录卡 ~600px/头像 96px、Me 头像 ~260px。**修正（现行代码）**：ContactCard `Avatar3D size=56`、Me 头像 72、会话行 `min-height:64px`。旧数字来自过期截图——P0 重拍后按新基线复评。
  修法：通讯录卡紧凑横向 ~76px（avatar 40、左对齐）；Me 用户卡横向 row（avatar 56）；会话行 64→56；行高密集档 `--row-h:32`/`--row-h-sm:24`；avatar 阶 `--avatar-sm/md/lg:32/40/64`。→ **P2/P3/P4**。
- **D3 居中对齐滥用**：通讯录 / Me 卡片全文居中 → 扫读差。修法：内容左对齐（`.me-page` align-center→stretch；`.contact-title` center→flex-start；`.empty-state-actions` center→flex-start）。→ **P3/P4/P6**。
- **D4 agent 12 色相用在名字文字 + 气泡左条**：蓝「Ryen」像超链接、与琥珀打架。
  根因：`MessageBubble` 内联 `borderLeft:3px solid hue` + `.bubble-name` 内联 `color:hue`。**`bubble.test.tsx:161–225` 当前钉住这两条**（须刻意重写）。
  修法：色相只喂头像环（`--agent-hue` 内联变量 + `box-shadow:0 0 0 2px var(--agent-hue)`，零偏移环 = 门禁合法，非 elevation）+ 群接力 6px 圆点；名字回 `--text-secondary`、删左条与 `--agent-hue-text-dark`。`agentHues()` 与 12 色板 contrast 契约不变。→ **P2**（含测试重写）。
- **D5 消息操作条常显噪声**：**修正机制**——`.bubble-actions` 已有 `opacity:0`+hover/focus-within 显现，但 `@container (max-width:975px)` 强制窄列常显，而默认 `--chat-col:768px < 975` → 正常窗口恒常显。断点由测试从 `MessageBubble.tsx` 源码按钮数推导（`actionButtons()` = `/bubble-action(?!s)/g` 匹配数 −1；今 7−1=6 → need 196 → 断点 975）。
  修法：内联收为 **3 枚**（复制 + 溢出触发 ellipsis + 仅朗读时的停止朗读），低频（赞/踩/编辑重发/重新生成/分支）进溢出 menu（`hidden`  attribute 收起，**DOM 常在**以保 `bubble-rewrite-actions.test` 的 aria-label 直点）；导出 `BUBBLE_INLINE_ACTIONS=3` 供测试导入 → need=28·3+4·2+8=**100**、断点=(100+48)·4−1=**591**、`--action-gutter` 下界 196→100。基线 `opacity:0` 与窄列常显块选择器不变。→ **P2**（含 derivation 测试更新）。
- **D6 圆角嵌套三层 / pill+28 滥用**：气泡>文件卡>预览 pill。修法：半径角色阶（控件 8 / 输入 8–12 / 卡 12–16 / 气泡 16 / 浮层 16–20 / 28 仅模态外层）；**至多两层嵌套、外层 ≤lg**；`.chat-input-col`/`.modal` radius-xl→lg；pill 仅 badge/chip/avatar；嵌套同心 inner=outer−inset。`--radius-xl` token 保留定义，只去嵌套用法。→ **P1/P2/P6**。

## 8. 后端只读增量（≤3，Plan agent 核实 routes/contract 后定稿 = 花 2）

1. **`GET /api/backups`** — `apps/server/src/routes/backup.ts`（现仅 POST /api/backup）：`readdirSync`/`statSync` 扫 `join(dataDir,'backups')`，返回 `{backups:[{name,bytes,createdAt}]}` 新→旧；目录缺→`{backups:[]}`。响应接口进新 `contract/backups.ts`。纯文件读，无写、不碰 AgentLoop。供 Me→工作区与数据备份历史。渲染层 `ApiClient.backups()` + 子页激活时 fetch（非定时）。
2. **`GET /api/conversations/:id/context`** — `routes/conversations.ts`；只读响应接口加进 `contract/conversations.ts`（additive，既有形状冻结）。返回 `{providerId,modelId,modelLabel,contextWindow:number|null,usedTokens:number|null}`，服务端解析：direct→成员 agent / group→调度员 agent；contextWindow 仅取 provider **声明**的 model 条目（不猜，缺→null，渲染层经 model-catalog 显示「上下文未知」）；usedTokens 取 `GET /api/conversations/:id` 已算的同一用量聚合。未知会话 404（同兄弟路由）。理由：composer 读数不许客户端 join 三份清单或订阅 chat store（perf 契约），会话切换+轮末各一次轻量 GET 是 memo-safe 路径，服务端解析保证读数与 loop 实际所用一致（尤其群聊）。

第三格**刻意不花**。原候选 `agents/status`（presence dot）非必需，舍；`providers/model-meta` 已存在于 `providerInfo()`，无需新增；`vibe/projects` 历史数据已客户端化（`.vibe-history-list`），无需新增。无既有端点改形状；无任何写新增。
